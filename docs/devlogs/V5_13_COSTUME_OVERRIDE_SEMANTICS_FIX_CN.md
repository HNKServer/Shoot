# NPPS4 v5.13 服装覆盖语义修复

## 根因

v5.09-v5.12 把每张卡牌自身的原始卡面也序列化到了可选 `costume` 字段。客户端把非空 `costume` 理解为“这张持有卡正在占用一套已登记衣装”，于是出现：

- 刚登记的卡牌自身显示 `SET`；
- 该衣装在同成员其他卡牌下变灰；
- 点击时提示衣装已被其他卡使用。

卡牌原始卡面本来已经由 `unit_id`、觉醒/显示 rank 与签名字段决定，不应再作为服装覆盖返回。

## 修复

- 未实际换装的卡牌：`costume = None`；
- 只有存在 `user_costume_dress` 记录时才返回 `costume` 覆盖；
- 关闭服装显示开关时也不返回伪造的“自身服装”；
- 无效/跨 Profile 的旧换装记录会清理并回到无覆盖状态；
- 一套已登记外观同一时间只能 `SET` 给一张持有卡牌；先解除原卡换装后才能给另一张使用。

## 衣柜登记是否可撤销

现存 CN/GL 客户端协议只有：

- `costumeList`
- `makeCostume`
- `dressUp`
- `costumeStatus`

没有“从衣柜删除登记”的 API。登记是永久收藏状态；`dressUp` 省略衣装字段只表示解除某张卡当前穿着的服装，不会删除衣柜条目。

## 数据库

无迁移。现有 `user_costume` 与 `user_costume_dress` 数据保留。

# NPPS4 v5.16：贴纸商店、招募和专用饰品重新验证版

## 1. 基线与废弃版本

本版重新从 v5.15 构建。此前生成的 `v5.16-sticker-gacha-accessory-contract-fix` 不作为基线，其中关于“重复池是哈希伪重复”“物品 2/3/4 是特殊招募券”“专用饰品需要两张相同卡”的结论均未沿用。

v5.15 的好友服装、导航伙伴显示、CN/GL 独有卡回退、Live 助战回退和 `costume:null` 防护全部保留。

## 2. CN 贴纸商店

### 日志能证明什么

CN 的 `/exchange/itemInfo` 正常返回 HTTP 200。客户端继续滚动后，在没有调用购买接口的情况下由 GLThread 触发 SIGTRAP。因此日志支持“列表惰性创建某一单元格时遇到不可渲染数据”，但日志本身不能指出具体哪一行。

### Master 逐行核验

使用源码包内的 `honoka_main.db`、精确 CN 9.7.1 `cn_client_master.db` 和 NPPS4 的 split-master 生成器重新生成 CN Master，然后逐项核对 849 个 `sticker_shop` 配置项：

- 804 项可由 CN 当前 Master 正常解释；
- 45 项引用 CN 不存在的对象：
  - 5 个背景：217、224、225、227、228；
  - 39 个称号：534–572；
  - 1 个回忆画廊项目：1698。

普通贴纸兑换的 Item 5 不会被误删。CN 的重建 `kg_item_m` 为空时，服务端会从当前 Profile 可见招募页的实际消耗物品中恢复可识别 Item ID，因此 Item 1、5、8 都被视为有效。

### 实现

- `itemInfo` 只返回当前 Profile Master 能解释的商品；
- `usePoint` 使用完全相同的判定，不能通过手工 ID 购买已隐藏行；
- 校验覆盖奖励 Item、称号、背景、贴纸种类、回忆画廊对象和所有价格贴纸 ID；
- Master 表无法查询时，该类别保持原行为，不会因为异常误删整个商店；
- 使用原版 NPPS4 的 `context_cacheable` 单次请求缓存，请求结束即释放，不建立用户级或进程级商店缓存；
- 日志会输出当前 Profile 的可见数量、排除数量和前 12 个排除项，方便真机再次定位。

## 3. 招募页与首页跳转

### 原版 NPPS4 的两对相似页面

以下页面全部保留：

- `bt-myus`：单次抽取；
- `bt-myus-10x`：十次抽取；
- `bt-aqua`：单次抽取；
- `bt-aqua-10x`：十次抽取。

它们使用相同缩略图、背景、概率和卡池范围，但抽取数量及总消耗不同。这是原版 NPPS4 明确配置的单抽/批量入口，不是哈希冲突，也不应删除。

招募列表保留四个独立页面。首页为了避免出现完全相同的公告图，只对视觉资源去重，并优先跳转到较高 `order` 的单抽页面；不会删除十连页面。

### 新增并恢复的 CN 页面

参考 honoka-chan 的 CN 最终服务配置，加入：

- 1718：μ's 大感谢祭；
- 1719：Aqours 大感谢祭；
- 1720：虹咲大感谢祭；
- 1721：Liella! 大感谢祭。

配置名称 `5K`、`5L`、`5M`、`5N` 的 Java 字符串哈希恰好分别为 1718–1721，因此服务端返回的是客户端使用的官方页面 ID。

每个页面按 honoka-chan 规则使用当前 CN Profile 自己的 Master 动态建立：

- SSR：70%；
- UR：30%；
- 11 连保证至少一张 UR；
- 支持 5/50 爱心和 Item 8 的 11 连券入口。

不会把 GL 卡牌 ID 写死进 CN。任一正概率稀有度在当前 Profile 中为空时，整个页面会隐藏而不是返回坏卡池。

虹咲和 Liella! 的原 NPPS4 特待生页保留为 GL 页面。所有既有配置池在发送前也会与当前 Profile 的 Unit Master 求交集。

首页公告栏直接从与 `/secretbox/all` 相同的投影结果生成，页面 ID、图片和点击跳转保持一致。

## 4. LOVEARROWSHOOT 的物品语义

NPPS4 自己的 `system/item.py` 明确规定：

- 2：友情点；
- 3：金币；
- 4：免费爱心。

它们不是三种招募券，因此继续作为 User 表中的余额补足，不创建伪造的普通 Item 库存行。

测试兑换码会明确补足：

- Item 1：普通招募券；
- Item 5：补助券/蓝券；
- 当前 Profile 所有招募页实际引用的其他券，包括大感谢祭使用的 Item 8；
- 当前 Item Master 中的其他真实物品；
- 贴纸商店作为奖励发放的真实 Item。

上述库存均补到 9999，重复输入只补足差额。金币、友情点、免费与付费爱心仍分别补到既有的大额测试目标。

## 5. 角色专用饰品

### 没有改成“两张同卡”

之前未经充分核实的 v5.16 曾把专用饰品创建改成“两张相同卡”。本版撤销该改动。

此前对 CN/GL 客户端的静态还原和 v4.46 审计确定：`accessory_special_m` 对应的是**消耗一张指定卡直接生成专用饰品**；只有不命中专用映射时才进入普通饰品抽选。v5.15 的这一业务逻辑保持不变。

本版也没有加入未经验证的“专用饰品未满级只能给原卡、满级才能给同角色”等穿戴限制。

### 测试资源补足

CN split Master 实测有 258 条专用饰品映射，全部目标均是当前 CN `unit_m` 中存在的普通卡。

`LOVEARROWSHOOT` 在发完整卡册后，会为当前 Profile 的每个专用饰品目标保证至少 3 张真正可选的副本：

- `active=True`；
- 非收藏；
- 不在任何队伍；
- 不是导航伙伴；
- 没有正在佩戴饰品。

这样即使原先唯一一张卡被放入队伍或设为伙伴，客户端仍能找到可消耗的对应社员。此改动只发生在测试兑换码执行时，不改变普通玩家的获得规则，也不建立常驻内存缓存。
